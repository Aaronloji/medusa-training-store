# CertPath: Medusa v2 Training Store

A full-stack **compliance training marketplace** built on **Medusa v2**. Learners buy OSHA, HIPAA, food-safety and workplace courses, progress lesson by lesson, and earn **verifiable certificates that expire**, just like real compliance training.

| | |
| --- | --- |
| 🛒 **Storefront** | https://medusa-training-store.vercel.app |
| 🛠️ **Admin dashboard** | https://certpath-medusa.onrender.com/app |
| 👤 **Demo learner** (storefront) | `demo@learner.com` / `demo1234` |
| 🔒 **Demo admin** (read-only) | `demo.admin@example.com` / `demo1234` |

> The backend runs on a free Render instance. If it has been idle, the first request can take up to a minute while it wakes up; the storefront shows a banner while that happens.

## What it demonstrates

**Medusa v2 backend** (`/backend`)
- **Custom module** `training` with `Course`, `Lesson` and `Enrollment` data models (DML + generated migrations), with CRUD generated by `MedusaService`.
- **Module links**: product ↔ course, plus a **read-only link** from enrollment → customer, all resolved with **Query** (`query.graph`) across modules.
- **Workflows with compensation**: `create-course`, `enroll-customer-from-order` and `complete-lesson`. Steps roll back if a later step fails, and `when` / `transform` handle conditional logic.
- **Subscribers**: `order.placed` grants course access automatically, and `enrollment.completed` issues the certificate.
- **Scheduled job**: expires certificates every night.
- **Custom API routes** with **Zod validation** and **customer auth middleware**. Prices are resolved per region through **`QueryContext`** and the Pricing Module.
- **Admin extensions**: a widget on the product page and a "Courses" page in the dashboard sidebar.
- **Read-only demo admin**: a custom `/admin/*` middleware blocks every write request from the public demo account. A **migration script** creates that account once on deploy.
- **Digital products**: no shipping profile and no inventory, so the standard cart → payment → order flow skips shipping.
- An **idempotent seed** (safe to run on every deploy) and unit-tested business logic.

**Next.js 16 storefront** (`/storefront`)
- Built with the official **`@medusajs/js-sdk`**: JWT customer auth, carts, payment sessions and order completion.
- Catalog with level filters, course pages, checkout, a "My learning" dashboard, a lesson player with progress tracking, a printable certificate, and a **public certificate verification** page.
- Responsive, accessible UI (Tailwind v4) with loading skeletons and a friendly state for when the backend is waking up.

## Architecture

```
 Next.js storefront (Vercel)                 Medusa v2 backend (Render)              Neon Postgres
 ─────────────────────────                   ────────────────────────────            ─────────────
 /courses ─── GET /store/courses ──────────► course module + product link ─────────► course, lesson,
 checkout ─── cart → payment → complete ───► core commerce modules                   enrollment tables
                                                  │ order.placed                     + core tables
                                                  ▼
                                          subscriber → enroll-customer-from-order workflow
 lesson player ─ POST …/complete-lesson ──► complete-lesson workflow
                                                  │ enrollment.completed
                                                  ▼
                                          subscriber → certificate issued
 /verify ───── GET /store/certificates/:code (public)

 nightly job: expire-certificates
```

## API

| Method | Route | Auth | Description |
| --- | --- | --- | --- |
| GET | `/store/courses?level=&region_id=` | publishable key | Catalog with region prices. Lesson content is hidden. |
| GET | `/store/courses/:idOrHandle` | publishable key | Course detail. |
| GET | `/store/customers/me/enrollments` | customer | Learner's courses, progress and lesson content. |
| POST | `/store/customers/me/enrollments/:id/complete-lesson` | customer | Records progress and issues the certificate at 100%. |
| GET | `/store/certificates/:code` | publishable key | Public certificate verification. |
| GET/POST | `/admin/courses` | admin | List courses, or create a course with lessons (optionally linked to a product). |
| GET/DELETE | `/admin/courses/:id` | admin | Course detail, or soft-delete. |
| GET | `/admin/products/:id/course` | admin | Course linked to a product (used by the admin widget). |

## Running locally

Requirements: Node 20+, and Docker (or a local PostgreSQL).

```bash
# 1. Backend
cd backend
npm install
cp .env.template .env
docker compose up -d                 # PostgreSQL + Redis
npx medusa db:migrate
npm run seed                         # prints the publishable API key
npx medusa user -e admin@example.com -p supersecret
npm run dev                          # http://localhost:9000/app

# 2. Storefront (in a second terminal)
cd storefront
npm install
cp .env.template .env.local          # paste the publishable key
npm run dev                          # http://localhost:3000
```

## Deployment (free tier)

| Piece | Service | Notes |
| --- | --- | --- |
| Database | **Neon** | Free Postgres. Use the connection string with `sslmode=require`. |
| Backend + Admin | **Render** | `render.yaml` blueprint. Migrations run on boot, and the seed runs when `RUN_SEED=true`. |
| Storefront | **Vercel** | Root directory `storefront`, env vars from `.env.template`. |
| Keep-alive | **GitHub Actions** | `keep-alive.yml` pings the backend every 10 minutes (set the repo variable `BACKEND_URL`). |

If the Render build runs out of memory, set `DISABLE_ADMIN=true` to skip the admin build.

## Design decisions

- **Idempotent enrollment.** `order.placed` can be delivered more than once, so the enrollment step skips courses the customer already has access to.
- **Business rules live in pure functions** (`backend/src/utils/progress.ts`) and are unit tested. Workflow steps stay thin.
- **Ownership checks return 404**, so the API never reveals that another customer's enrollment exists.
- **Paid content is private.** The catalog never exposes `content_url`; only the learner's own enrollments do.
- **Certificates are verifiable and expire**: a unique code, a public verification endpoint, and a nightly expiry job. Recurring certification is central to compliance training.
- **The public admin demo is safe**: reviewers can browse the whole dashboard, but writes return `403` for the demo account, while real admins keep full access.
- **Prices come from Medusa's Pricing Module** via `QueryContext` instead of being duplicated in the course model.
