# CertPath: Medusa v2 Training Store

A full-stack **compliance training marketplace** built on **Medusa v2**. Learners buy OSHA, HIPAA, food-safety and workplace courses, progress lesson by lesson, and earn **verifiable certificates that expire**, just like real compliance training.

| | |
| --- | --- |
| 🛒 **Storefront** | https://medusa-training-store.vercel.app |
| 🛠️ **Admin dashboard** | https://certpath-medusa.onrender.com/app |
| 👤 **Demo learner** (storefront) | `demo@learner.com` / `demo1234` |
| 🔒 **Demo admin** (read-only) | `demo.admin@example.com` / `demo1234` |

> The backend runs on a free Render instance. If it has been idle, the first request can take up to a minute while it wakes up. Server-rendered pages come from the cache, and the storefront shows a banner while the API wakes up.

## What it demonstrates

**Medusa v2 backend** (`/backend`)

| Concept | Where |
| --- | --- |
| **Custom module**: `Course`, `Lesson` and `Enrollment` data models (DML + generated migrations), with CRUD generated by `MedusaService` | `src/modules/training` |
| **Module links** (product ↔ course), a **read-only link** (enrollment → customer), and **Query** across modules | `src/links` |
| **Workflows with compensation** (`create-course`, `update-course`, `enroll-customer-from-order`, `complete-lesson`), plus `when` / `transform` | `src/workflows` |
| **Workflow hooks** into core flows: `createCartWorkflow`, `addToCartWorkflow` and `completeCartWorkflow` refuse a course the learner already owns | `src/workflows/hooks` |
| **Custom notification provider** (Resend email) next to the built-in local provider for the **admin notification feed**, sent from a workflow with `sendNotificationsStep` | `src/modules/resend-notification`, `src/workflows/send-certificate-notification.ts` |
| **Subscribers** (`order.placed` → enroll, `enrollment.completed` → certificate email) and a **scheduled job** (nightly certificate expiry) | `src/subscribers`, `src/jobs` |
| **API routes** with **Zod validation**, customer auth, and per-region prices through **`QueryContext`** and the Pricing Module | `src/api` |
| **Admin extensions** built with the **JS SDK + TanStack Query**: a Courses list, create modal, edit page with learners, and a product widget | `src/admin` |
| **Read-only demo admin**: an `/admin/*` middleware rejects writes from the public account, and a **migration script** creates it on deploy | `src/lib/demo-admin.ts`, `src/migration-scripts` |
| **Realistic demo data** created through core workflows: orders via cart → payment → capture, promotions, a B2B price list, customer groups, taxonomy. Resumable, and runs once on deploy | `src/scripts/demo-data.ts` |
| **Production topology**: Redis event bus, workflow engine and locking, plus **server/worker split** (`workerMode`), Dockerfile and compose file | `medusa-config.ts`, `Dockerfile`, `docker-compose.production.yml` |

**Next.js 16 storefront** (`/storefront`)
- **Server-rendered catalog and course pages**: rendered per request, with Store API responses in the Next.js Data Cache for 5 minutes. They include per-course metadata, Open Graph images, **schema.org `Course` JSON-LD**, and a `sitemap.xml` and `robots.txt`. If the API is unreachable, pages fall back to client-side fetching instead of failing, and an outage is never baked into a prerendered page.
- Built with the official **`@medusajs/js-sdk`**: JWT customer auth, carts, payment sessions and order completion.
- Checkout, a "My learning" dashboard, a lesson player with progress tracking, a printable certificate, and **public certificate verification**.

## Architecture

```
                         ┌──────────────────────────── Medusa v2 ────────────────────────────┐
 Next.js (Vercel)        │                                                                   │
 SSR catalog ──────────► │ /store/courses ── Query (course + product link + QueryContext)    │
 checkout ─────────────► │ create/add/complete cart ── hooks.validate: already owned? ──┐    │
                         │                    │ order.placed                            ✗ 400 │
                         │                    ▼                                              │
                         │   subscriber → enroll-customer-from-order workflow                │
 lesson player ────────► │ complete-lesson workflow ── emits enrollment.completed           │
                         │                    ▼                                              │
                         │   subscriber → send-certificate-notification workflow            │
                         │        ├─ email ─► Resend provider (custom module provider)       │
                         │        └─ feed  ─► local provider → admin notification bell      │
 /verify ──────────────► │ /store/certificates/:code (public)                                │
                         │ nightly job: expire-certificates                                  │
                         └───────────────────────────────────────────────────────────────────┘
                              Postgres (Neon)        Redis (optional: event bus, workflows, locks)
```

### Production topology

The live demo runs a single "shared" instance on a free tier. For real traffic the same code splits into processes through configuration only:

```
          ┌── server (MEDUSA_WORKER_MODE=server) ── HTTP, admin, migrations
 LB ─────►│
          └── server …                          ┐
                                                ├── Redis: event bus · workflow engine · locking
              worker (MEDUSA_WORKER_MODE=worker)┘   Postgres
              subscribers · scheduled jobs · async workflow steps
```

```bash
cd backend && docker compose -f docker-compose.production.yml up --build
```

When `REDIS_URL` is set, `medusa-config.ts` switches on the Redis event bus, workflow engine and locking modules. Without it, Medusa uses its in-memory versions (local development, free hosting).

## API

| Method | Route | Auth | Description |
| --- | --- | --- | --- |
| GET | `/store/courses?level=&region_id=` | publishable key | Catalog with region prices. Lesson content is hidden. |
| GET | `/store/courses/:idOrHandle` | publishable key | Course detail. |
| GET | `/store/customers/me/enrollments` | customer | Learner's courses, progress and lesson content. |
| POST | `/store/customers/me/enrollments/:id/complete-lesson` | customer | Records progress and issues the certificate at 100%. |
| GET | `/store/certificates/:code` | publishable key | Public certificate verification. |
| GET/POST | `/admin/courses` | admin | List courses, or create a course with lessons (optionally linked to a product). |
| GET/POST/DELETE | `/admin/courses/:id` | admin | Course detail, update through the `update-course` workflow, or soft-delete. |
| GET | `/admin/products/:id/course` | admin | Course linked to a product (used by the admin widget). |

## Running locally

Requirements: Node 20+, and Docker (or a local PostgreSQL).

```bash
# 1. Backend
cd backend
npm install
cp .env.template .env
docker compose up -d                 # PostgreSQL + Redis
npx medusa db:migrate                # schema + demo admin + demo data
npx medusa user -e admin@example.com -p supersecret
npm run dev                          # http://localhost:9000/app

# 2. Storefront (in a second terminal)
cd storefront
npm install
cp .env.template .env.local          # paste the publishable key printed by the migration
npm run dev                          # http://localhost:3000
```

## Design decisions

- **Duplicate purchases are blocked where they start.** Hooks on cart creation and add-to-cart give the learner a clear message, and the `completeCartWorkflow` hook is the final guard. Expired certificates can be bought again to renew.
- **Notifications go through a workflow**, not straight from the subscriber. It retries and is observable, and a failed email never undoes the learner's progress.
- **Idempotent enrollment.** `order.placed` can be delivered more than once, so the enrollment step skips courses the customer already has access to.
- **Business rules live in pure functions** (`progress.ts`, email templates), so they are unit tested. Workflow steps stay thin.
- **Ownership checks return 404**, so the API never reveals that another customer's enrollment exists.
- **Paid content is private.** The catalog never exposes `content_url`; only the learner's own enrollments do.
- **Prices come from Medusa's Pricing Module** via `QueryContext` instead of being duplicated in the course model.
- **The public admin demo is safe.** Reviewers can browse everything, writes return `403` for the demo account, and real admins keep full access.
